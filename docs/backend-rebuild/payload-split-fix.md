2026-10-12。用户要求修复观察中确认的前两项；先将观察测试升级成期望行为回归，再修改生产实现。没有新增工作流、调度器或外部服务。

## 异常比较

新增局部比较输入检查：有限JSON值、最大深度128（根深度0）、最多10000个值节点。迭代检查预算后才进入原有规范化，避免运行时递归溢出；预算集中于 COMPARISON_LIMITS，低于实验中2048正常/4096异常的运行时边界，不把平台崩溃阈值当作支持范围。

仅检查参与参数谓词或结果字段谓词的值；旁支不参与判断。声明的match/equals超预算明确拒绝。证据中的非有限值/超预算子树不能形成该谓词的候选，但不阻止扫描后续独立合法执行。不对任意内部异常做 blanket catch，也不把异常值转换成null或相等。

每次核验缓存比较key，不跨核验持有payload。原生sourceEventSeqs关联、错误结果拒绝、序号窗口、发布身份和最大匹配继续保留。

验证：真实DSH arguments溢出仍由上游拒绝；renderer目标溢出、深对象/数组均得到NO_GO，责任保留；追加真实正常工具执行后GO，重建host从持久日志/责任记录读取仍GO。新的完整插件测试覆盖turn-stopping反馈NO_GO、离线agent随后产生正常证据、turn完成及重建恢复，修复前为turn error。

预算边界另测128层与10000节点支持、超一单位拒绝且正常后继证据可闭合。tool-completed不读取业务结果字段；它仍不代表某字段正确。预算是当前明确的能力边界，不是任意大小JSON的安全/资源沙箱；JSON解析字节量与整个host长期内存不由此保证。

## 等价最大分配下的拆分

拆分核验先为retain动作求匹配，再对其余动作增广。增广只重分配见证，不丢弃已匹配动作，最终仍是全局最大完成数量。只有retain全部匹配、defer全部未分配时才接受。因此允许在等价最大分配间选择，但不能随意延后额外已经可以全部完成的工作。

正常verifyCommitment仍使用原声明顺序的确定匹配；split的revision.basis保存提议对应的准确实际执行。异常历史防御、一次拆分、完整分区、原断言保留、继承pending和版本锚点不变。

四格矩阵全部合法提议均接受且重复确定。独立穷举2304个提议：666个可行提议全部接受，错误接受0，合法误拒0；原观察中288个等价误拒已消除。两次真实执行不能假称只完成一次。Controller测试确认任一等价retain都可行，后继仍需声明后的新执行才能清除pending；重建后责任状态一致。
