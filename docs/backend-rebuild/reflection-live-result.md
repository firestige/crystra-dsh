## 具体发现及事实层级

| 类别 | 发现 | 当前证据与后续验证方向 |
| --- | --- | --- |
| 正确性 | 宽条件动作可能抢先占用窄条件唯一可用的调用，产生顺序相关的误拦 | 模型独立指出，并诚实标为源码假设。本地助手另行复现：两项承诺、两次实际调用，只改变动作顺序便出现 NO_GO / GO。该复现未提供给模型。需要重叠条件及顺序变换回归；若语义是存在互不重复的匹配，应考虑确定的最大匹配，而非仅按特异性排序 |
| 鲁棒性 | 精确序号边界、错误结果、双重关联、null与缺失、嵌套路径、拆分失败分支等覆盖不足 | 是覆盖分析，不是已经发现这些分支实现错误。建议用 native-shaped 表驱动用例逐项验证 |
| 鲁棒性 | 文本片段拼接、同一调用多个结果/块的选择依赖上游生产者约定 | 未验证假设。应先查 DSH 原生结果序列化和最终性规则，再判断是否需要改代码，不据此扩大到任意不合法 JSON 的防御 |
| 性能 | 实际核验耗时随无关历史增加 | 有真实基准。建议一次性建立调用/结果索引、减少重复解析；必须保留关联、锚点、错误处理和匹配语义，并在相同输入下做候选对照 |
| 性能 | 大量匹配参数但结果缺失/失败的调用可能导致更差的嵌套扫描开销 | 未测的源码复杂度假设。现有成功调用+消息噪声基准不覆盖，需额外改变动作数、无结果调用数和 payload 大小 |
| 性能 | split 的 versions 保存完整旧 goal，可能重复嵌套既有历史，导致增长过快 | 未实验复现。模型同时指出合法连续 split 次数受初始动作数限制。应测逐次合法拆分的序列化大小、内存和耗时，再评估扁平记录或父版本引用 |

本地顺序问题复现：`artifacts/backend-rebuild/reflection-overlap-probe.mjs` 及同名 `.json`。本次没有实施上述建议；反思结果不等于代码已修复或改进已验证。

## 过程中的实际问题

最终报告前有两次格式拒绝：第一次把实验 id 写成带解释的句子，第二次在 file 字段附加函数说明。它们不是未执行测试的虚构结论；但确实违反接口要求，分别收到 Unknown experiment evidence 和 Invalid or unread finding location。模型根据工具反馈改为精确收据 id / 文件名，第三次报告被记录。没有放宽校验，也没有人工代填。说明接口描述还可更清晰，减少无价值的修复轮次；这些结构/引用检查不负责决定代码质量。

共5次模型响应、3次报告提交尝试。DSH记录token合计45,718，其中cacheReadTokens 26,624、inputTokens 13,498、outputTokens 5,596；这是适配器用量字段求和，不是订阅账单金额。只用 request/context 事件计数会漏算后续轮次，本次按 assistant/message 用量记录核对。

反思已正常结束并保存结果，但模型实验脚本在输出完成结果后仍驻留；本地无模型的恢复读取进程能正常退出。完成持久结果验证后已终止本次实验进程。驻留原因尚未定位，因此不能声称真实模型路径的清洁退出已验收。

## 本轮能支持的结论
