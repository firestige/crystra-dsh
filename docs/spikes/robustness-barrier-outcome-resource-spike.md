# 结果歧义防御与有界资源观察

## 目标与边界

重复结果块是否确实被拒绝？在固定规模连续核验中，时间和内存是否表现出值得处理的增长？

时间盒：30 分钟。本轮先观察，不自动修复实现。输入、随机种子、版本、断言和异常原文全部保存；失败、超时与未完成分开记，不把缺少复现写成安全证明。

## A：异常结果防御

保持同一调用身份准确，人工构造一条结果消息内两个同 callId 的 tool-result 块：成功/失败、失败/成功、成功/成功；全部应 NO_GO。另测试一个目标块加一个不同 ID 的块、正常多个文本片段，观察当前选择规则，不能将后两类自动视为重复结果。

已有重复 tool/result 事件回归继续保留，并验证检查失败后的控制器责任不变。上述均标注人工异常；不声称正常 DSH 会产生。

原生路径另观察正常返回、工具抛错和持久化恢复重放：同一调用在读取后的日志中是否出现重复块/重复结果。只读既有日志，检查恢复是否重现同一份事件而非再次 append；这仅支持这些路径，不能推出所有故障窗口保证。

## B：资源观察

先完成匹配正确性实验，避免对错误结果计性能收益。固定 Node/依赖版本，记录机器、输入字节数、事件数和动作数。

- 历史 100/1,000/10,000 条，动作固定20；无结果与结果不符调用 50/100/200；另一个匹配压力组为64动作×256调用。
- 每场景独立进程，预热10次、采样30次；报告单次耗时中位数和p95、RSS及heapUsed。时间数字为本机观察，无产品 SLA。
- 修复前后在共同合法输入上比较：准确关联、唯一调用ID，先确认最大完成数和证据有效性相同。交替运行旧/新实现，共三对独立进程；语义已改变的重复ID/歧义输入只比较预期正确性，不计加速。
- 稳定输入连续核验1,000次，及逐批增长至10,000条历史各核验一次，观察缓存是否跨核验积累。每100次采样；单独使用 --expose-gc 的探针在阶段间记录回收后的堆。不能把RSS未回落直接等同内存泄漏。

旧实现每场景最多10秒，整体资源实验上限15分钟。若受机器噪声影响，只报告扫描计数与测量范围，不得挑最好数字。该实验不是多小时长程稳定性证明，也不测共识服务延迟或整体调度收益。

## 产物

重复块回归、原生恢复事件观察、隔离进程性能/内存原始数据。证据目录 `artifacts/backend-rebuild/outcome-resource-spike/`。

## 完成条件

每个计划用例都有输入、实际结果和证据路径；未执行项明确标记。结论区分已复现、当前边界、未复现与仍待决策。达到时间盒即汇总，不通过扩大场景追求全面证明。

## 研究结果与决策

### A 结果：已执行，3 项测试通过

执行：`OUTCOME_SPIKE_SAVE=1 node --test test/backend/outcome-spike.test.mjs`。未改生产实现。

- **人工异常**：同一消息内同 callId 的成功/失败、失败/成功、成功/成功重复块均 NO_GO。一个目标块加一个不同 ID 块为 GO；一个目标块内正常多个文本片段拼接完整 JSON 为 GO。两者不等于重复目标结果。
- **责任防御**：通过真实 Controller declare → split → 继承声明建立非空 pending；人工重复块及重复结果事件均 NO_GO，active、pending、history、nextStep 不变；恢复 Controller 后状态一致。lastCheck 会记录失败，不能把这项合法审计变化误说成整个 state 不变。
- **原生 DSH 正常与抛错**：确定性离线模型分别调用正常工具及实际抛错工具。两次调用各有唯一原生结果事件、唯一匹配块和准确 sourceEventSeqs；抛错结果带 isError。未出现重复结果。完整承诺 NO_GO，原责任保留。
- **原生持久化只读**：退出原 Context 后，在新 Context 内两次 read-open；事件完全相等，原生日志和 Crystra journal 字节不变。
- **原生 resume**：两个新 Context 依次调用 agents.resume，不发新任务。原事件前缀完全保留；结果事件仍为原来两条，Crystra journal 不追加。DSH 合法增加 session/end-seed 标记，故“resume 后整个日志字节不变”假设被观察否定；这不是重复工具结果，也不是缺陷。初始失败观察保留，避免悄悄改口。

证据：`artifacts/backend-rebuild/outcome-resource-spike/outcomes-evidence.json` 保存人工输入、判定、原生事件、声明/检查/恢复状态以及前后日志文本；`outcomes-test.log` 保存最终通过日志；`outcomes-initial-observation.log` 保存初始 end-seed 差异。

结论：当前重复结果块/事件防御及责任保留获得观察支持，正常完成与工具抛错的原生持久化、只读、恢复路径未复现重复结果。不代表崩溃中断、所有故障窗口或所有插件都不会产生异常结果。本轮未注入崩溃、损坏尾部，也未覆盖 zstd 编码；不能将此范围扩张为完整 DSH 恢复安全证明。

## B：资源观察结果

2026-10-12 已执行。前三组批量 CPU 探针停止后，串行运行 60 个独立进程（10 个场景 × 2 个实现 × 3 轮），每进程10次预热、30次单独计时，交替旧/新顺序；另2个进程观察连续与增长历史。全部退出0，无预算超时。基准代码为修复准确关联前保留的 association-fix/barrier-before.js；输入采用两版共有的合法唯一调用ID语义，不把重复ID或歧义修复计入速度对比。

运行前独立核对已知完成数量、GO/NO_GO、调用与结果准确对应、参数资格、成功标记和执行不复用。对多解图不要求两版选定相同见证。本轮生产代码未修改。

### 单机测量

以下是三轮各自中位数的范围，单位毫秒；p95及全部原始30次样本、RSS、heapUsed都在JSON中。

| 输入 | 旧实现中位数范围 | 当前实现中位数范围 |
| --- | --- | --- |
| 20动作，10,000条无关历史 | 1.712–1.732 | 0.231–0.241 |
| 5动作，200次无结果调用 | 0.554–0.583 | 0.023–0.025 |
| 5动作，200次结果不符调用 | 1.857–2.559 | 0.414–0.430 |
| 64动作×256调用，完全重叠候选 | 20.753–21.237 | 3.004–3.115 |

这些共同输入上索引版确有较低的本机核验耗时，方向与扫描计数一致；不能推断包含DSH调度、共识查询和模型调用的端到端收益。小样本p95仍受JIT/GC等影响，不作为生产SLA。

### 内存观察

- 稳定1,000条噪声输入连续核验1,000次：回收后heapUsed约4.90MB起，后半程约4.98–4.99MB，未观察到随调用数持续上升的趋势；RSS约61.3MB增至67.4MB后趋稳。
- 历史每批增长100条，直到10,000条，共100次核验；每批输入在独立函数返回后释放再GC。回收后heapUsed约4.61MB起，后半程约4.87–4.91MB；RSS约52.8MB增至80.0MB。RSS增长不能单独证明泄漏，已释放输入时堆没有随累计历史线性增长。
- 这是短程、显式GC、隔离纯核验观察；没有覆盖真实长期host持有的会话历史、journal增长、全部DSH插件或多小时运行。没有宣称系统不存在内存泄漏。

### 初次样本与复测

首次样本保留为 *-initial.json：payload agent 报告一条约1秒的小测试可能重叠；同时增长内存探针初版可能保留最后一份输入。为避免混淆，输入创建改在独立栈帧内，等待其他实验停止后完整重跑。结论只引用最终无 initial 后缀的数据；初次记录未删除。

### 产物

`scripts/backend/barrier-resource-spike.mjs`：可复现隔离进程 runner。

`artifacts/backend-rebuild/outcome-resource-spike/`：resource-timing.json、resource-memory-stable.json、resource-memory-growing.json、resource-run.log、resource-initial-note.txt。元数据包含Node、平台、CPU、起始负载和源码/探针SHA256。最终运行约7.67秒是执行记录，不是端到端产品性能。

### 结论

重复结果块/事件防御与受测原生恢复路径已得到证据；索引版在共同合法输入上减少核验耗时，受测规模内未发现持续累计堆增长。当前无新增实现修改建议；任意故障窗口恢复与多小时host稳定性仍未证明。
