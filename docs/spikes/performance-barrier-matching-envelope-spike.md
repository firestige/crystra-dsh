# H5：动作与执行规模对匹配成本的影响

主问题：在真实可构造的承诺和工具执行规模下，候选图与重分配是否造成不可接受的时间或内存开销？

静态观察：候选构建遍历动作×执行并保留边，增广匹配受图密度影响。已有 64/256 规模已知答案图及随机小图 oracle 正确性测试；原反思 benchmark 固定 20 动作/20 执行，仅变化消息噪声，不能证明这些维度的性能。

实验：
1. 固定数据小且合法，以 A=1/20/64/256、X=A 或 4A，选稀疏、稠密、重分配链三个图族；用分阶段方案最多 16 个样例，不做全排列。
2. 先保持 X=A 逐档增加 A；再在 A=64 固定时增加 X；最后固定 A/X 改密度与图族。用已知答案构造及现有 oracle 校验最大匹配数量，不只看最终 GO。
3. 增加无关工具执行对照，和纯消息噪声区分。记录 A/X/边数、耗时、峰值内存及匹配数量。边数由实验数据构造独立计算，不修改产品插桩。
4. 原生 DSH 承诺/工具事件验证代表样例可达；规模基准可直接使用这些事件的合法构造，明确它不是额外真实模型自主运行证明。

保护：独立子进程，父进程每样例 15 秒硬截止，堆 256 MiB、RSS 512 MiB 终止，触顶停止递增。每例重复 3 次，轮换顺序，报告中位数/范围，不从少量样本推断总体 p95。

完成标准：区分已验证正确性、实际测量的性能包络和理论复杂度；只有出现可复现且与目标任务相关的成本问题，才讨论索引或更换算法。
