# 等价匹配下的拆分分配语义

## 目标与边界

一次执行同时满足两项承诺时，当前拆分允许什么？声明顺序造成的限制是证据错误，还是尚未明确的分配策略？

时间盒：20 分钟。本轮先观察，不自动修复实现。输入、随机种子、版本、断言和异常原文全部保存；失败、超时与未完成分开记，不把缺少复现写成安全证明。

## 最小实验

两项不同 action id、相同工具与参数的承诺 A/B；只有一次真实成功执行。固定事件不变，分别测试声明顺序 AB/BA，以及 retain A、defer B 与 retain B、defer A，得到四格矩阵。

补两个对照：

- 两次不同事件序号的真实执行：两项都完成，不能把任一项假称未完成；包括文本 callId 重复情况。
- 两项不同参数、只有 A 的执行：只能保留 A，不能保留 B。

每次从同一份未修订原承诺独立运行，避免“一份承诺只能拆分一次”的防御干扰实验。重复相同输入 20 次检查确定性；比较 verdict、matches、missing、revision basis 与 pending。

## 独立判定与策略分界

用小规模穷举分别求：最大完成数量，以及 proposal 指定的 retain 集是否存在互不复用的真实证据。每次分配必须保持完整责任分区、准确执行身份和原断言不变。

两个策略都列出观察结果，但不擅自选定：

1. 固定分配策略：拆分服从核验选定的确定分配，某些等价提议会被拒绝。
2. 提议约束策略：只要 retain 可获得完整独立证据，且 defer 确实是剩余未分配责任，就允许等价分配；不能把已经可全部完成的动作随意延后。

输出是否存在顺序依赖、依赖是否导致责任丢失或仅影响可接受提议。若只是策略差异，提交具体矩阵供选择，不按 bug 自动修复。

## 产物

四格矩阵、对照组与穷举结果。证据目录 `artifacts/backend-rebuild/split-allocation-spike/`。

## 完成条件

每个计划用例都有输入、实际结果和证据路径；未执行项明确标记。结论区分已复现、当前边界、未复现与仍待决策。达到时间盒即汇总，不通过扩大场景追求全面证明。

## 研究结果与决策

2026-10-12 已执行，生产实现未修改。独立测试 `test/backend/split-allocation-spike.test.mjs` 的 3 个实验通过。这里“通过”表示观察与当前固定分配行为一致、责任不丢失，**不表示已选定产品语义**。

### 四格矩阵

只有一次合格执行时，原始核验均为 NO_GO、完成数量均为 1：

| 声明顺序 | retain / defer | 当前 split | 提议约束 oracle |
|---|---|---|---|
| A B | A / B | 接受，basis 指向 A 的调用 seq=11 | 可行 |
| A B | B / A | 拒绝，`split lacks actual completed/unfinished facts` | 可行 |
| B A | A / B | 拒绝，同上 | 可行 |
| B A | B / A | 接受，basis 指向 B 的同一调用 seq=11 | 可行 |

每格相同输入重复 20 次，verdict、matches、missing、revision basis、pending 和错误均一致。由此确认：分配有声明顺序依赖，但不是随机行为。拒绝时不更改输入，接受时 kept + pending 完整保留所有原断言，revision basis/anchor 可指回准确执行。

### 对照与独立枚举

- 不同参数，仅 A 有执行：两种声明顺序均只允许 retain A。
- 两次真实执行：两项都完成，任何将一项 defer 的提议均被拒绝；包括文本 callId 重复但调用事件序号不同的情况。
- 独立 oracle 递归穷举全部部分分配，不调用生产 matcher。覆盖 64 个三动作/两执行资格图、6 种声明顺序、6 种非空 retain/defer 分区，共 2304 提议。当前接受 378 项，均存在相同最大完成数量的独立合法分配，未发现错误接受；另有 288 项在提议约束策略下可行，但当前固定分配拒绝。
- 每个核验的完成数量均等于独立 oracle 的最大完成数；见证均来自合法资格边，调用事件序号不复用。
- 接受提议的 version=2、单层旧版本、basis、anchor、pending 来源标识及原断言均有断言；验证与拆分不修改原输入。

### 证据与范围

证据目录 `artifacts/backend-rebuild/split-allocation-spike/`：

- `environment.json`：Node/平台及被测生产源码 SHA-256；本实验无随机输入。
- `matrix.json`：四格完整输入和实际状态。
- `controls.json`：12 组完整对照输入和状态。
- `enumeration.json`：图编码/锚点和 2304 项完整实际结果、oracle 结论。
- `test.log`：独立运行结果。

输入是人工构造的原生形状事件，目的是隔离分配语义；没有运行真实模型，不能由此推断模型提交此类提议的频率。没有测控制器持久化、恢复、pending 后继调度；当前责任与状态结论只覆盖 `compileCommitment` / `verifyCommitment` / `splitCommitment` 纯函数输出。大型图及资源测量由并行实验负责。

### 结论与待决策

已确认 **固定分配策略的顺序依赖**，没有在本组发现责任丢失、错误执行归属或重复使用执行。按固定分配契约，这些拒绝符合现行实现；按提议约束契约，288 项是本可接受却被拒绝的提议。不能在未确定契约时将其直接定性为算法缺陷。

需要产品选择的是：当多种最大分配均合法时，是否允许 proposal 参与选择分配。若选择固定分配，可维持当前实现并公开这一约束；若选择提议约束，需另行实现并验证“retain 完整有据、未凭空推迟可全部完成工作”的规则。本轮不作选择，也不更改生产实现。
