# H4：合法大 payload 的实际增量开销

主问题：现有合法 JSON 工具参数/结果，在何种大小开始让 Barrier 带来明显额外开销？

静态观察：深度和节点上限约束参与比较的子树，不能推出总体字节/解析/复制上限；完整参数解析和结果拼接解析仍可能处理很大的非目标字段。已有深度 128、节点 10000、数值溢出回归，不重复把它们当未覆盖缺陷。

实验：
1. 合法 JSON，字符串取 4 KiB、256 KiB、4 MiB、16 MiB；分别位于被比较字段、未比较侧字段；另用浅层宽对象。排除稀疏数组/cycle，避免和 H1 混淆。
2. 相同数据比较：原生 DSH 工具链不挂 Barrier、挂 tool-completed、挂 result-equals。分别测完整链路和独立核验增量，记录输入/输出字节、比较子树规模、耗时、进程峰值内存、GO/NO_GO。
3. 每档独立子进程，轮换顺序，重复 3 次报告中位数及范围；记录 Node/DSH 版本。已有真实运行轨迹作为量级参照，不修改原记录。

保护与判读：父进程硬截止每样例 15 秒，子进程堆上限 256 MiB，触顶即停止递增；堆限不等于 RSS 上限，父进程同时监测 RSS，超过 512 MiB 终止。实验保护不是产品已有预算。区分 DSH 序列化/持久化成本与 Barrier 增量；失败仅说明该测试包络的限制，是否需要产品预算另作决定。

完成标准：得到规模—成本曲线和首个受限样例或明确未触及边界。没有实测前不新增任意产品大小限制。
