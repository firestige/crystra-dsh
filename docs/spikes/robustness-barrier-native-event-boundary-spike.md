# H3：异常事件能否通过原生证据入口

主问题：异常事件能否从真实 session 证据源到达 Barrier，造成误闭合、异常或恢复差异？

静态观察：证据由插件 flush 后读取 session.snapshotEvents，agent 不提交证据对象。实时 append 分配序号；恢复验证序号和消息结构。实时 append 与恢复的结构校验并不完全相同，需实测，不能概括为“DSH 都拦住了”。

实验分层：
1. helper 阳性对照：missing/NaN/fractional seq、重复 call seq、缺失 content 数组。记录错误关联或异常是否出现，仅用于证明探针有效。
2. 正常 DSH 工具链：正常成功、失败、错误渲染返回；观察规范化后的真实事件形状和 Barrier 结果。不得手填证据冒充原生事件。
3. 受信任插件的 live session.append：用真实调用锚点尝试缺失/错误 content 与 block 结构；序号只能使用原生生成值。记录 append/flush/snapshot/Barrier 哪一层接受或拒绝，以及承诺状态是否被误推进。
4. 独立临时 JSONL 副本注入异常序号和结构后恢复；观察是否在 Barrier 前拒绝。NaN 无法合法 JSON 表示，单列为 JS helper 控制，不伪装成合法落盘数据。
5. 每个异常样例附正常事件对照；异常后补发合法工具事件，检查未完成责任能否正常闭合；对被接受的异常实时事件再恢复，核对实时与恢复差异。

完成标准：分别给出正常模型链路、宿主插件误用、存储损坏的可达性结论及原生事件/状态证据。已有多结果事件关联测试复用，不重做整套。此实验不承诺容忍任意损坏。
